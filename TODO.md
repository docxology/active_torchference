## Workflowz review — 2026-11-10

- [ ] **ATR-001 — P1: Refresh moving goals on every runner step.** `ExperimentRunner.run_episode` obtains `preferred_obs` once before the loop and reuses it for every `agent.step`, so `OscillatorEnvironment`'s time-varying target is never tracked by the orchestrator. Move preference acquisition into the loop immediately before planning and add a runner regression using a changing target. Evidence: `active_torchference/orchestrators/runner.py:83-104`, `active_torchference/environment.py:323-343`. Acceptance: from the repository root, `uv run --with-requirements requirements.txt pytest -q tests/test_runner.py -k refreshes_preference` passes and records a different preference on successive steps. Dependencies/constraints: none; preserve the existing observation/action ordering.

- [ ] **ATR-002 — P1: Make `Config` serialization round-trip losslessly.** `Config.to_dict` serializes `dtype` as a string and omits `num_belief_iterations`, while `from_dict` forwards both values without restoration; consequently `Config.from_dict(config.to_dict())` cannot construct an agent with the serialized dtype and silently resets a custom belief-iteration count. Decode the dtype, include every constructor field, and test construction from the round-tripped mapping. Evidence: `active_torchference/config.py:43,79-106`, `docs/METHOD_REFERENCE.md:316-340`. Acceptance: `uv run --with-requirements requirements.txt pytest -q tests/test_config.py -k round_trip` passes, preserving `torch.float64`, a non-default `num_belief_iterations`, device, and all other fields and successfully constructing `ActiveInferenceAgent`. Dependencies/constraints: retain JSON-compatible `to_dict` output used by `Logger.save_config`.

- [ ] **ATR-003 — P1: Restore complete agent checkpoints.** `save_state` omits both neural models, and `load_state` restores only posterior mean/log-std plus action parameters; it ignores the serialized prior parameters. Loading into a new agent therefore does not reproduce subsequent predictions and `reset()` uses the wrong prior. Persist and restore `generative_model` and `transition_model` state dictionaries and belief priors. Evidence: `active_torchference/agent.py:319-368`, `active_torchference/beliefs.py:133-140`. Acceptance: `uv run --with-requirements requirements.txt pytest -q tests/test_agent.py -k checkpoint_restores` passes, checking model parameters and priors exactly and showing identical reset beliefs and identical next deterministic step from original and restored agents under matched RNG state. Dependencies/constraints: preserve existing checkpoint fields so current readers can be migrated deliberately; document any checkpoint-version change.

- [ ] **ATR-004 — P1: Make the epistemic EFE term policy-dependent.** `PolicyEvaluator.evaluate_policy` expands the same detached current-belief entropy across every rollout, and `predicted_obs_std` is a fixed constant; hence the epistemic contribution cannot distinguish candidate policies or contribute action gradients, despite driving the exploration examples. Replace the constant surrogate with a documented rollout-dependent uncertainty/information estimator connected to the optimized action samples. Evidence: `active_torchference/agent.py:184-194`, `active_torchference/policy.py:215-227`. Acceptance: `uv run --with-requirements requirements.txt pytest -q tests/test_policy.py -k epistemic_gradient` passes, demonstrating unequal epistemic values across suitable rollouts and different seeded action updates for different `epistemic_weight` values. Dependencies/constraints: preserve the lower-EFE-is-better convention and document the estimator and its Monte Carlo seeds; do not claim scientific superiority from the unit test.

- [ ] **ATR-005 — P2: Honor `precision_prior` in variational free energy.** The constructor stores `precision_prior`, but `compute` never reads it, so changing the documented “stronger prior” control has no effect. Apply it to the complexity term consistently with the prior parameterization and add a numerical regression. Evidence: `active_torchference/free_energy.py:24-35,68-75`, `docs/BELIEF_AND_POLICY_UPDATES.md:278-287`. Acceptance: `uv run --with-requirements requirements.txt pytest -q tests/test_free_energy.py -k prior_precision` passes, showing that increasing prior precision strengthens the complexity penalty for a fixed non-prior posterior and changes belief updates in the documented direction. Dependencies/constraints: avoid double-counting precision already encoded in `prior_std`; state the chosen convention in the method documentation.

- [ ] **ATR-006 — P2: Wire action-selection temperature or remove the control.** `Config.temperature` is advertised as controlling action stochasticity, but `PolicyEvaluator.select_action` always samples with unscaled `action_std`; only the unrelated standalone softmax utility consumes a temperature. Apply the configured temperature to stochastic policy/action sampling and reject non-positive values. Evidence: `active_torchference/config.py:21-22,48-49`, `active_torchference/policy.py:276-294`. Acceptance: `uv run --with-requirements requirements.txt pytest -q tests/test_policy.py -k action_temperature` passes, showing lower seeded sampling dispersion at lower temperature, unchanged deterministic actions, and `ValueError` for zero/negative temperature. Dependencies/constraints: update the configuration and policy documentation to distinguish Gaussian action temperature from `utils.softmax` temperature.

- [ ] **ATR-007 — P2: Reject zero-length episodes before averaging.** `run_episode(max_steps=0)` skips the loop and divides both totals by zero. Validate a positive step limit at entry (and test the boundary) rather than failing after environment reset. Evidence: `active_torchference/orchestrators/runner.py:74-85,132-133`. Acceptance: `uv run --with-requirements requirements.txt pytest -q tests/test_runner.py -k invalid_max_steps` passes, expecting an immediate descriptive `ValueError` for zero and negative limits while `max_steps=1` still completes.
